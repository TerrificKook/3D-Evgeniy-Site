# Staging сайта инженерной мастерской

Локальный сайт для 30-дневной проверки спроса на три типа B2B-задач:

1. некритичные пластиковые детали по физическому образцу;
2. корпуса и компоненты для электроники;
3. производственная оснастка, кондукторы, фиксаторы и держатели.

Сайт не является публично запущенным. Форма работает в безопасном mock-режиме, внешние получатели, домен, DNS, реклама и production-аналитика не подключены.

## Что находится в проекте

- `PROJECT_BRIEF.md` — рабочий бриф без выдуманных данных;
- `PROJECT_PLAN.md` — этапы, риски и критерии готовности;
- `SITE_MAP.md` — маршруты и их роль;
- `CONTENT_GAPS.md` — полный список данных до публичного запуска;
- `DECISIONS.md` — журнал нетривиальных решений;
- `STATUS.md` — текущий статус;
- `research/` — исходные материалы исследования;
- `site/` — приложение staging.

## Запуск в Windows PowerShell

Требуется Node.js версии 22.13 или новее.

```powershell
cd "C:\Users\user\YandexDisk\VibeCode-Studio\3D Evgeniy Site\site"
npm install
npm run dev
```

После запуска откройте адрес, который покажет терминал. Обычно это:

```text
http://127.0.0.1:3000/
```

Остановка локального сервера: нажмите `Ctrl+C` в том же окне терминала.

## Проверка проекта

```powershell
cd "C:\Users\user\YandexDisk\VibeCode-Studio\3D Evgeniy Site\site"
npm run typecheck
npm run lint
npm run check:content
npm run build
```

Можно выполнить все staging-проверки одной командой:

```powershell
npm run verify
```

Команда публичной готовности должна оставаться заблокированной, пока не заполнены обязательные параметры:

```powershell
npm run check:production
```

## Где менять содержание

- общие настройки и будущие контакты: `site/config/site.ts`;
- карточки трёх направлений: `site/content/services.ts`;
- подробные продуктовые страницы: `site/content/service-pages.ts`;
- кейсы: `site/content/cases.ts`;
- список неподтверждённых данных: `CONTENT_GAPS.md`.

Не добавляйте неподтверждённые параметры в компоненты страниц. Сначала подтвердите факт у Динара или Евгения, затем обновите централизованный файл и отметьте пункт в `CONTENT_GAPS.md`.

## Как добавить реальный кейс

1. Скопируйте объект-шаблон в `site/content/cases.ts`.
2. Замените `slug` и `title`.
3. Заполните только факты, которые подтверждены производственной карточкой и разрешены к публикации.
4. Поставьте `status: 'client'` только для реальной работы.
5. Добавьте публичные поля в `verifiedFields`.
6. Всё неподтверждённое оставьте в `draftFields`.
7. Добавьте изображения в `site/public/cases/<slug>/` и пути в `images`.
8. Запустите `npm run verify`.

`draftFields` не передаются в публичный компонент кейса.

## Как подключить форму позже

Сейчас форма:

- сохраняет черновик только в браузере;
- передаёт текст локальному API только для серверной валидации;
- не сохраняет данные на сервере;
- не загружает файлы;
- не отправляет email, Telegram или CRM.

До подключения production-адаптера нужно определить получателя, хранилище, типы и размер файлов, срок удаления, права доступа, политику обработки данных и текст согласия. После этого добавляется новый адаптер рядом с `site/lib/lead-adapter.ts`, а mock остаётся доступным для локальной проверки.

## Как подключить Яндекс Метрику

1. Скопируйте `site/.env.example` в `site/.env.local`.
2. Заполните только числовой `NEXT_PUBLIC_YANDEX_METRIKA_ID`.
3. Перезапустите локальный сервер.
4. Проверьте события без персональных данных.

Без ID внешний скрипт не загружается. В коде предусмотрены события:

`cta_click`, `service_select`, `lead_form_start`, `lead_form_step_complete`, `file_attach`, `lead_form_submit_success`, `lead_form_submit_error`, `messenger_click`, `phone_click`, `case_view`.

## Checklist перед публичным запуском

- [ ] Закрыты обязательные пункты `CONTENT_GAPS.md`.
- [ ] Утверждены бренд, домен, контакты, география и реальный SLA.
- [ ] Евгений подтвердил материалы, габариты, допуски, мощность и стоп-лист.
- [ ] Есть хотя бы один реальный кейс с разрешением на публикацию.
- [ ] Утверждены политика обработки данных и согласие.
- [ ] Подключён и проверен безопасный канал заявок и файлов.
- [ ] Указан production URL и ID Метрики в переменных окружения.
- [ ] Форма прошла тестовый путь без отправки реальному получателю до отдельного разрешения.
- [ ] `npm audit`, `npm run verify` и `npm run check:production` проходят.
- [ ] Владельцы отдельно разрешили production deployment и рекламу.

## Развёртывание

Текущий этап не включает deployment. Когда владельцы отдельно разрешат публикацию:

1. заполните production-переменные окружения;
2. подключите реальный адаптер формы и хранилище;
3. замените staging-информацию на утверждённую политику;
4. выполните все проверки из checklist;
5. соберите проект командой `npm run build`;
6. разверните собранную версию в выбранной инфраструктуре;
7. проверьте публичные маршруты, форму, Метрику, canonical, sitemap и robots;
8. только после этого подключайте рекламный трафик.

Домен, DNS, hosting и рекламные кабинеты в рамках текущей работы не изменялись.
